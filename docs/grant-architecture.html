Budget Planner — Architecture

User-facing flow & technical build pipeline

Layer 1 — User-Facing Flow

Diagram 1: Project Lifecycle Overview

The four phases of a grant budget project form a continuous cycle. Configuration feeds into planning, which drives actuals tracking, then monitoring closes the loop with a feedback arrow back to Plan & Allocate when adjustments are needed. The CLI command bar below shows which entry point triggers each phase.

Diagram 2: Excel Sheet Relationships

Config sits at the hub, feeding named ranges and table data to every downstream sheet. Arrows show the direction of data flow; green arrows denote cross-sheet formula references. The highlighted purple arrow from Capacity back to Plan is the critical reverse flow where SUM formulas aggregate individual allocations. _META documents all sheets but carries no data flow.

Diagram 3: RAG Escalation Model

The workbook uses a three-tier traffic-light system (Green / Amber / Red) implemented via Excel conditional formatting. Lower-priority rules (green, amber) are applied first; higher-priority rules (red) are added second and override. Thresholds are derived from the actual openpyxl FormulaRule definitions in each builder module.

Layer 2 — Technical Pipeline

Under the hood, the Budget Planner is a Python pipeline that generates a fully-wired Excel workbook. Every sheet is built by a dedicated module, and each builder returns a layout dictionary used by downstream steps.

Diagram 4: Build Pipeline

The 14-step common pipeline is shared by both init (from seed data) and rebuild (from existing workbook). The init/rebuild fork converges at step 1. Step 5 is the critical cross-sheet wiring where Capacity FTE values flow back into Plan via SUM formulas. Steps 6 and 9 show the Trends split: the skeleton (current_month named range) is created early, content is populated after Actuals and Summary are built.

Diagram 5: Round-Trip / Rebuild Flow

The rebuild cycle preserves user-entered data (Capacity FTE allocations and Actuals EUR costs) while regenerating all formulas, formatting, and cross-sheet wiring. Skeleton mode (--skeleton) clears Capacity allocations but always keeps Actuals. A snapshot/restore mechanism enables scenario comparison.

Diagram 6: Module Dependency Map

Three horizontal bands show call flow from CLI orchestration through sheet builders to shared infrastructure. Solid arrows indicate always-used dependencies; dashed arrows are conditional (init-only or rebuild-only). Each builder returns a layout dictionary consumed by downstream steps.
